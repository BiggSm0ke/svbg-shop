# Установка

Коротко: склонировать репозиторий, запустить `sudo bash deploy/install.sh`, ответить на вопросы. Здесь подробности: что именно делает установщик, где что лежит и как поставить всё руками.

## Перед установкой

- Сервер на Ubuntu 22.04 / 24.04 или Debian 12, root по SSH. Памяти от 1 ГБ: если меньше 2 ГБ и swap нет, установщик создаст `/swapfile` (до 2 ГБ, но оставит на диске не меньше 4 ГБ свободными).
- Свободно на диске: 5 ГБ для установки с нуля, 3 ГБ для одного бота. Если меньше, установщик остановится ещё до установки.
- Порты 80 и 443 не заняты (если заняты, см. «Свой веб-сервер» ниже).
- A-записи на IP сервера: `panel.`, `sub.`, `bot.` для установки с нуля, только `bot.` для остальных режимов.
- Токен бота от @BotFather.

## Код

```bash
sudo -i
apt update && apt install -y git
git clone https://github.com/BiggSm0ke/svbg-shop.git /opt/svbg-shop
cd /opt/svbg-shop
```

Папка с кодом нужна и после установки: из неё собирается образ (`docker build -t svbg-shop:local .`, публичного образа нет) и в ней `svbg update` делает `git pull`. Её путь установщик запоминает в `/opt/svbg/install.conf`.

## Запуск

```bash
sudo bash deploy/install.sh
```

Если `sudo` на сервере нет (бывает на голом Debian), запускайте от root просто `bash deploy/install.sh`.

Сначала установщик ставит то, без чего не обойтись: `whiptail`, `curl`, `jq`, `openssl`, `git`. Потом показывает меню. Все вопросы идут в начале, затем сводка и «Начинаем?». После «Да» вопросов больше не будет.

Повторный запуск безопасен. Уже созданное не пересоздаётся, секреты не генерируются заново, на вопросы с готовым ответом можно ответить «оставить как есть». Если бот уже стоит, меню сразу предложит «Обновить».

Лог: `/var/log/svbg-install.log`. Пароли и токены в него не пишутся и на экран не выводятся. Даже в списке процессов (`ps`) их не видно: в `curl`, `jq` и контейнер они передаются через stdin или переменные окружения.

## Режимы

### Всё с нуля

Для пустого сервера. Спросит домены, токен бота, логин и пароль админа панели, способ связи бота с панелью, ваш Telegram ID и ID админ-группы (последние два можно пропустить).

По шагам:

1. Swap, если памяти меньше 2 ГБ. Docker через официальный скрипт get.docker.com.
2. Панель Remnawave в `/opt/remnawave` по официальной инструкции: `docker-compose-prod.yml` и `.env.sample` из github.com/remnawave/backend. Секреты (`APP_SECRET` или `JWT_*`, `METRICS_PASS`, `WEBHOOK_SECRET_HEADER`, пароль PostgreSQL) генерирует `openssl rand` на сервере. В `.env` прописываются `FRONT_END_DOMAIN`, `PANEL_DOMAIN`, `SUB_PUBLIC_DOMAIN` и вебхуки в бот.
3. Caddy в `/opt/caddy` в сети `remnawave-network`. Сертификаты Let's Encrypt он получает сам для всех трёх адресов.
4. Админ панели и API-токен через API панели: `GET /api/auth/status`, затем `POST /api/auth/register` (или `/api/auth/login`, если админ уже есть) и `POST /api/tokens` с правами `*` на 10 лет. Запросы идут на `http://127.0.0.1:3000` с заголовками `X-Forwarded-For` и `X-Forwarded-Proto: https`, без них панель соединение закрывает.
5. Страница подписки в `/opt/remnawave/subscription`: образ `remnawave/subscription-page`, `REMNAWAVE_PANEL_URL=http://remnawave:3000`, `TRUST_PROXY=1` и свой API-токен.
6. Бот: база `svbg` и роль `svbg` в PostgreSQL панели, сборка образа, настройки, запуск.
7. `ufw allow 80/tcp` и `443/tcp`, если ufw включён. Если выключен, установщик его не включает.

Пароль админа Remnawave принимает только длиной от 24 символов, с заглавными и строчными латинскими буквами и цифрами. Установщик проверит это до отправки. Пароль нигде не сохраняется.

### Бот рядом с панелью

Панель уже стоит в `/opt/remnawave` на этом сервере. Спросит адрес бота, токен бота, доступ к панели (готовый API-токен, логин и пароль админа или «пропустить»), способ связи с панелью и владельца.

Что меняется у панели: в её `.env` включаются вебхуки (`WEBHOOK_ENABLED=true`), к `WEBHOOK_URL` через запятую дописывается `http://svbg-shop:8080/webhooks/remnawave`, затем контейнер `remnawave` пересоздаётся. Если вебхуки уже уходили другому боту, его адрес и общий секрет остаются как были. Секрет из `.env.sample` (он публичный) установщик заменит, если вебхуки до этого были выключены, иначе предупредит.

База бота: отдельная база `svbg` с ролью `svbg` в контейнере `remnawave-db`. Если в `/opt/svbg/pg` уже лежит база от прежней установки, бот останется на своём контейнере PostgreSQL.

### Только бот

Панель на другом сервере. Спросит адрес панели (`https://…`), её API-токен (проверит запросом), адрес бота (можно пропустить), секрет вебхуков панели (если он у панели уже есть), токен бота и владельца.

Бот получает свой контейнер `postgres:17-alpine`, сеть Docker `svbg-network` и Caddy только для `bot.`-адреса. На сервер панели установщик не ходит. Строки для её `.env` он кладёт в `/opt/svbg/panel-webhook.env` (права 600): перенесите их и выполните там `docker compose up -d --force-recreate remnawave`.

Без адреса бота работает всё, кроме касс с вебхуками и вебхуков панели. Бот всё равно сверяется с панелью по расписанию.

## Что где лежит

| Путь | Что там |
|---|---|
| `/opt/svbg/docker-compose.yml` | compose бота. Пишет установщик, правки руками затрёт следующий запуск |
| `/opt/svbg/data/` | данные бота (права 700, владелец uid 1000): `.env`, бэкапы, картинки |
| `/opt/svbg/data/.env` | все настройки бота. Синхронизирован с `/settings` |
| `/opt/svbg/data/.pg_password` | пароль роли `svbg` в PostgreSQL |
| `/opt/svbg/install.conf` | что выбрано при установке: режим, домены, сеть. Без секретов |
| `/opt/svbg/pg/` | данные своего PostgreSQL, если бот не в базе панели |
| `/opt/remnawave/` | панель Remnawave (`docker-compose.yml`, `.env`) |
| `/opt/remnawave/subscription/` | страница подписки |
| `/opt/caddy/` | Caddy: `Caddyfile`, `docker-compose.yml` |
| `/usr/local/bin/svbg` | команда управления ботом |
| `/var/log/svbg-install.log` | лог установщика |

В compose бота нет `env_file`: бот сам читает `data/.env`. Контейнер `svbg-shop` слушает `127.0.0.1:8080`, ограничен 512 МБ и подключён к сети панели, поэтому видит её как `http://remnawave:3000`.

Настройки, которые пишет установщик: `BOT_TOKEN`, `DATABASE_URL`, `BOT_MODE=polling` (только при первой установке), `PUBLIC_URL=https://bot.…`, `REMNAWAVE_URL`, `REMNAWAVE_TOKEN`, `REMNAWAVE_WEBHOOK_SECRET`, а также `OWNER_IDS` и `ADMIN_CHAT_ID`, если вы их указали. Пустые ответы ничего не затирают.

## Caddy и свой веб-сервер

Для `bot.`-адреса Caddy пропускает наружу только `/webhooks/*`, `/tg/*`, `/m/*` и `/r/*`. На всё остальное он отвечает 404, админки снаружи нет.

Блоки, которые пишет установщик, стоят в Caddyfile между метками `# >>> svbg:имя` и `# <<< svbg:имя`, остальное в файле он не трогает. Если Caddy уже работает (например, тот, что ставили для панели по инструкции Remnawave), установщик найдёт его Caddyfile по монтированию контейнера, допишет блок, проверит конфиг `caddy validate` и перечитает его. Не прошла проверка: вернёт прежний файл и скажет об этом.

Если 80/443 занимает nginx или что-то ещё, Caddy не ставится. Готовые блоки для Caddy и nginx будут в `/opt/svbg/reverse-proxy.txt`.

## Ссылка владельца и мастер

В конце установщик печатает одноразовую ссылку `https://t.me/<бот>?start=setup_…`. Кто первым её откроет, станет владельцем. Если вы указали свой Telegram ID, ссылки не будет: просто откройте бота. Новая ссылка: `svbg owner-link` (прежняя после этого не работает).

Мастер `/setup`:

1. Панель. Если адрес и токен уже вписаны, мастер только проверит подключение. Иначе спросит их, сообщения с токеном удалит. Новое подключение проверяется до сохранения: при ошибке остаётся прежнее.
2. Админ-группа. Приватная группа с включёнными темами, выбирается кнопкой. Бот станет админом (управление темами, закрепление, удаление сообщений) и создаст темы.
3. Вебхуки панели. Если установщик их уже настроил, шаг проходит сам. Иначе бот покажет строки для `.env` панели. Пишите их без пробелов после запятых и без комментариев в строке, затем перезапустите панель.
4. Готово: чеклист.

Дальше тарифы (`/plans`), тексты (`/edit`) и кассы (`/settings`), см. [settings.md](settings.md) и [payments.md](payments.md).

## Команда `svbg`

`status`, `logs [-f]`, `up`, `down`, `restart`, `update [--force]`, `backup`, `restore <файл>`, `set KEY VALUE`, `edit`, `owner-link`, `show-key`, `version`. Подсказка: `svbg help`.

`svbg set` передаёт значение в контейнер через stdin, так что в списке процессов его не видно. В истории shell оно останется, поэтому секреты лучше вписывать в боте или через `svbg edit`.

## Обновление и откат

```bash
svbg update
```

То же, что пункт «Обновить» в меню установщика:

1. `git pull --ff-only` в папке с кодом (от имени владельца папки, если это не root).
2. Сборка нового образа. Прежний сохраняется как `svbg-shop:previous`.
3. Бэкап `pre_update`. Если он не получился, обновление останавливается (`svbg update --force` пропустит бэкап).
4. Бот останавливается, миграции базы (`python -m svbg migrate`, перед изменением схемы он сам делает ещё бэкап `pre_migrate`).
5. Запуск и проверка, что бот отвечает.

Не смог сделать `git pull` (нет сети до GitHub или в папке есть локальные правки): предупредит и соберёт то, что лежит в папке.

Откат:

```bash
docker tag svbg-shop:previous svbg-shop:local && svbg restart
svbg restore /opt/svbg/data/backups/<файл pre_update>   # если миграции уже поменяли базу
```

## Бэкап и восстановление

- Автобэкап: настройки `BACKUP_ENABLED`, `BACKUP_AT` (время по `TIMEZONE`), `BACKUP_KEEP`, `BACKUP_TO_TELEGRAM`, `BACKUP_PASSWORD`. В архиве база, загруженные файлы и зашифрованная копия `.env`.
- Вручную: `svbg backup`, файлы в `/opt/svbg/data/backups`.
- Восстановление: `svbg restore <файл> [части…]`. Спросит `yes`, сделает бэкап текущей базы (`pre_restore`), остановит бота, очистит базу, загрузит данные и запустит бота. Пароль бэкапа спросит сам, или возьмёт из `--password-file` либо `SVBG_BACKUP_PASSWORD`. В командной строке пароль не передаётся.
- Переезд на другой сервер: установщик, `svbg restore` и тот же `SECRET_KEY` (`svbg show-key` на старом сервере).

В образе бота `pg_dump` 18: он снимает дампы и с PostgreSQL 18 панели, и со своего 17-го.

## Удаление

`sudo bash deploy/install.sh` → «Удалить бота». Остановит и удалит контейнер и образ бота, уберёт блок бота из Caddy и адрес бота из `WEBHOOK_URL` панели. Панель, страница подписки и Caddy остаются.

Данные (`/opt/svbg/data`) удаляются только после отдельного «Да». Перед этим установщик предложит сделать свежий бэкап и скопировать все бэкапы в `/root/svbg-backups-<дата>`. Базу `svbg` в PostgreSQL панели он удалит, только если вы подтвердите и это.

## Вручную, без установщика

Пример compose с ботом и своим PostgreSQL: `deploy/docker-compose.yml`.

```bash
docker build -t svbg-shop:local /opt/svbg-shop
mkdir -p /opt/svbg/data && chown 1000:1000 /opt/svbg/data && chmod 700 /opt/svbg/data
cp /opt/svbg-shop/deploy/docker-compose.yml /opt/svbg/
openssl rand -hex 24 > /opt/svbg/data/.pg_password && chmod 644 /opt/svbg/data/.pg_password
cd /opt/svbg
docker compose run --rm --no-deps bot python -m svbg env init
```

Затем впишите в `data/.env` `BOT_TOKEN` и `DATABASE_URL=postgresql://svbg:<пароль из .pg_password>@db:5432/svbg` и запустите `docker compose up -d`. Если панели на этом сервере нет, уберите из compose четыре помеченные строки сети `remnawave-network`. Наружу публикуйте только через reverse proxy с HTTPS (порт бота `127.0.0.1:8080`), пути те же, что в разделе про Caddy.
