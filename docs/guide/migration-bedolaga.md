# Переезд с Bedolaga

Порядок переезда по шагам. До переключения SvBG ничего не меняет у Bedolaga: её бот, база, `payments.db` и панель только читаются.

## Что переносится, а что нет

Переносятся пользователи, подписки, кошелёк (баланс), оплаты по кассам, незакрытые счета (как `pending`, их потом добивает reconciler), промокоды и их использования, рекламные кампании, рефералка, настройки (по таблице соответствия ключей), белый список IP Guard, активные блоки IP Guard и LTE.

Не переносятся токены и секреты Bedolaga (боевой токен панели вводится заново, старый отзывается через 72 ч после переключения); `WL_QUOTA_EMERGENCY_HOLD` и `RELEASE_ON_DISABLE`; режим `off` для LTE (в SvBG его нет, Bedolaga `off` превращается в `shadow`); wlq-admin (его функции уходят в админку бота); отдельный сервис оплаты со страницы подписки, если он у вас был (его останавливают вместе с Bedolaga).

## 1. Подготовка

1. Поднимите новый бот на тестовом токене и в тестовом чате.
2. Снимите копию БД Bedolaga (`pg_dump`) и копию `payments.db`.
3. В Remnawave создайте API-токен только на чтение и проверьте его:
   ```
   svbg cutover probe-panel --token-file <файл> --expect read-only
   ```
   Токен только читает, если проба даёт 403; 404 значит, что токен пишущий, и shadow запускать нельзя.
4. Разберите хвосты в Bedolaga: `held`/ручной разбор в Pay, непроведённые команды LTE, неотпущенные блоки IP Guard.
5. Проверьте готовность:
   ```
   svbg cutover check
   ```
6. Подготовьте конфиг Caddy: вебхуки касс (`/rollypay-webhook`, `/cryptobot-webhook`, `/api/pay/...`) на `/webhooks/pay/<instance>/<token>`.

## 2. Теневой режим и отчёт сверки

В панели в `WEBHOOK_URL` допишите через запятую второй URL (адрес нового бота), секрет прежний, без пробелов.

Импорт идёт в три режима: dry-run (пробный, всё откатывается), shadow (каждый день на свежем дампе, в панель ничего не пишется) и apply (финальный). Сверка в режиме shadow:

```
svbg cutover shadow-run --source-dsn-file <файл с DSN копии БД Bedolaga> --token-file <read-only токен панели>
```

DSN можно передать и через `SVBG_SHADOW_SOURCE_DSN`. Адрес панели берётся из `--panel-url` или из `REMNAWAVE_URL` в `data/.env`.

В отчёте проверки С1-С12: число пользователей, подписок и оплат, сумма кошельков 1:1, незакрытые счета, привязка подписок, **ноль операций, которые писатель отправил бы в панель**, блоки LTE и IP Guard, рефералка, журнал уведомлений, диплинки. Расхождения закрываются правилами импорта (`import_overrides`), прогон можно повторять сколько угодно. **Из shadow выходят, когда все проверки зелёные три дня подряд.**

Команды импорта:

```bash
# настройки из .env Bedolaga: сначала проверка, потом применение
svbg import settings --env /path/to/bedolaga/.env
svbg import settings --env /path/to/bedolaga/.env --apply

# данные: dry_run → shadow (каждый день до переключения) → apply в день T0
svbg import bedolaga --mode dry_run --source-dsn-file /root/bedolaga.dsn --env /path/to/bedolaga/.env --json report.json
svbg import bedolaga --mode shadow  --source-dsn-file /root/bedolaga.dsn --token-file /root/panel-readonly.token
svbg import bedolaga --mode apply   --source-dsn-file /root/bedolaga.dsn --env /path/to/bedolaga/.env
```

DSN копии базы Bedolaga лучше передавать файлом (`--source-dsn-file`) или переменной `SVBG_IMPORT_SOURCE_DSN`: аргумент командной строки виден в списке процессов. В режиме shadow нужен токен панели только на чтение: бот ничего не пишет в панель.

## 3. День переключения (T0)

Выберите ночь по МСК, не 00:00-00:10 и не около 03:00. Заранее объявите: 15-30 минут бот может отвечать с задержкой, оплаты не теряются.

1. T-60 мин: не трогайте админку Bedolaga, кабинет, wlq-admin и панель.
2. T-20: включите в Bedolaga техработы.
3. T-5: последний shadow-прогон, все проверки зелёные.
4. T0: остановите Pay, затем wlq-admin, затем Bedolaga; `docker update --restart=no <контейнеры>`. Не меняйте перед остановкой `WL_QUOTA_ENABLED`, `ENFORCE_SCOPE`, `IP_GUARD_ENABLED`: иначе блоки снимутся.
5. Проверьте webhook боевого токена:
   ```
   svbg cutover webhook-info --token-file <файл>
   ```
   Если там остался чужой URL, удалите его: `svbg cutover delete-webhook --token-file <файл> --expect-url <url> --yes`.
6. Снимите `pg_dump` и копию `payments.db` (точка отката).
7. Финальный импорт (apply) из этого снимка, затем все проверки С1-С12. Если есть красные, откатывайтесь.
8. Переключите Caddy на новые маршруты вебхуков, включите инстансы касс (`PAY_<SLUG>_ENABLED=true`). Подписанный запрос с неверной подписью должен дать 401 (маршрут жив).
9. Введите боевой `BOT_TOKEN`; `pending_update_count` должен упасть до 0.
10. В Remnawave замените read-only токен на боевой со скоупами и включите писатель; в `WEBHOOK_URL` панели оставьте только наш URL. Проверка: `svbg cutover probe-panel --token-file <файл> --expect write`; сверка должна давать 0 операций.
11. Старые ссылки: Caddy `/wlq/` на заглушку, `?ref=<код>` на `t.me/<бот>?start=<код>`.
12. Модули защиты: IP Guard в выбранном режиме; LTE сначала `shadow` на 1-2 цикла (около 20 мин), затем `on`. В `shadow` импортированные блоки продолжают действовать, новые не ставятся.
13. Снимите техработы и объявление.

Если между шагами 4 и 9 прошло больше часа, ничего страшного: Telegram хранит апдейты до 24 ч, касса повторяет вебхук, а reconciler добирает пропущенное. Stars `pre_checkout` в окне истекает через 10 с: пользователь видит ошибку, деньги не списываются.

## 4. Откат

Откатываться стоит, если проверки красные и за 20 минут их не починить, писатель делает неожиданные операции (больше 20 PATCH за 10 минут вне плана), не проходят зачисления или массово падают /start, оплаты и «Подключиться».

Откатиться можно в течение 72 ч после T0 или до первого необратимого массового действия: рассылки, массового revoke, больше 5 новых блоков за сутки, массовой правки сроков. Перед таким действием бот предупредит, что окно отката закроется, и попросит подтверждения.

Сам откат занимает около 15 минут, хвост незакрытых счетов тянется до 48 ч:

1. Остановите выставление новых счетов, подождите минуту и включите техработы:
   ```
   svbg pay freeze
   svbg set MAINTENANCE_MODE=true
   ```
   Если после T0 бот ставил новые блоки LTE: `svbg lte release --since T0`, пока писатель панели работает.
2. Выгрузите журнал изменений (оплаты, кошелёк, сроки, рефералка, блоки, новые пользователи, отдельно все `pending`-счета):
   ```
   svbg cutover export-rollback --since <T0 в ISO 8601 с поясом> [--out файл.json]
   ```
3. Незакрытые счета нового бота: по умолчанию Caddy целиком возвращается на Bedolaga, а новый бот остаётся в режиме «только платежи» (reconciler опрашивает свои `pending`: 48 ч RollyPay, 24 ч CryptoBot); оплаченные попадают в список для ручного начисления в Bedolaga. Для импортированных счетов перед начислением проверьте по `external_id`, не зачислила ли их сама Bedolaga.
4. Верните Caddy (`Caddyfile.bedolaga`) и старый `WEBHOOK_URL` панели.
5. Запустите Bedolaga на нетронутой БД, затем Pay и wlq-admin.
6. Доиграйте журнал вручную: оплаты и кошелёк через админку Bedolaga, сроки подписок до ночной сверки правьте по списку.
7. Отзовите боевой токен панели у нового бота; когда неистёкших `pending` не осталось, остановите бот.

Отдельной команды для техработ нет, их включает ключ `MAINTENANCE_MODE`. Список оплаченных счетов берите из файла `export-rollback`. До T0 пробегитесь по `svbg --help`, чтобы не искать команды в момент отката.

## После переключения (через 72 ч)

У Pay удалите `USER_NOTIFY_BOT_TOKEN`, `BEDOLAGA_API_TOKEN`, `REMNAWAVE_TOKEN`, отзовите токен Web API и старый токен панели, `payments.db` в архив. Callback RollyPay переведите на прямой адрес нового бота и уберите перенаправление в Caddy.
