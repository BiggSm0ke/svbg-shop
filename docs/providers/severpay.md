# SeverPay

Оплата по ссылке SeverPay: СБП, НСПК E-com, T-Pay, SberPay, MirPay и другое, что подключено вашему магазину. В API выбрать способ нельзя, покупатель выбирает на странице. Только приём платежей, без выплат.

## Настройки инстанса

В кабинете SeverPay (severpay.io/panel) нужен ваш магазин.

- `PAY_SEVERPAY_MID`: ID магазина (`mid`), число.
- `PAY_SEVERPAY_TOKEN`: секретный ключ магазина. Бот подписывает им каждый запрос, и тем же ключом проверяются вебхуки.
- `PAY_SEVERPAY_LIFETIME_MIN` (расширенное): срок жизни ссылки, от 30 до 4320 минут. Если пусто, действует значение SeverPay, 1440 минут (сутки).
- `PAY_SEVERPAY_RETURN_URL` (расширенное): куда вернуть покупателя. Пусто значит ссылка на бота.
- `PAY_SEVERPAY_CHECK_IP` (расширенное, по умолчанию выключено): принимать вебхуки только с официальных адресов SeverPay.
- `PAY_SEVERPAY_BASE_URL` (расширенное): `https://severpay.io/api/merchant`.

Бот принимает через SeverPay только рубли. Если аккаунт SeverPay работает в другой валюте, бот не включит кассу и скажет об этом. Минимум и максимум платежа определяются аккаунтом, публично их нет.

## Вебхук

В запросе создания адреса вебхука нет, его вписывают в кабинете. В документации SeverPay точное место в кабинете не названо, ищите поле `WEBHOOK_URL` в настройках магазина, а если не найдёте, спросите поддержку (t.me/severpay_info). Адрес:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

Бот отвечает `200` с `Content-Type: application/json` и телом `{"status": true}`, именно так SeverPay ждёт подтверждение.

## Подпись и IP

Подпись вебхука считается не по сырым байтам, а по JSON, перекодированному так, как это делает PHP. Это хрупко, поэтому вебхук `success` сам деньги не зачисляет: бот заново спрашивает платёж у SeverPay (`/payin/get`) и решает по ответу. Остальные статусы применяются сразу.

`PAY_SEVERPAY_CHECK_IP` включайте, только если бот видит настоящий адрес отправителя, то есть без обратного прокси. За Caddy проверка отвергнет все уведомления. Подпись проверяется в любом случае.

Создание платежа бот не повторяет вслепую: идемпотентности по номеру заказа SeverPay не обещает, и повтор мог бы выставить второй счёт. SeverPay требует email и ID клиента, бот подставляет вместо них непрозрачный хеш пользователя (вид `…@telegram.org`), настоящий Telegram ID наружу не уходит.

Возвратов в API SeverPay нет, делайте их в кабинете. Тестового режима нет.
