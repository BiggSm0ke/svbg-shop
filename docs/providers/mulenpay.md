# MulenPay

Эквайринг: карты и СБП, рубли. Передаёт чеки по 54-ФЗ, платёжная страница на стороне MulenPay.

## Настройки инстанса

Все три значения в кабинете MulenPay (mulenpay.ru): «Магазины», нужный магазин, «Настройки».

| Поле | Откуда |
|---|---|
| `PAY_MULENPAY_API_KEY` | «API-ключ» магазина |
| `PAY_MULENPAY_SECRET_KEY` | «Секретный ключ» магазина |
| `PAY_MULENPAY_SHOP_ID` | числовой ID в столбце «ID» списка магазинов |

Чековые поля нужны для 54-ФЗ. По умолчанию подходят для УСН и самозанятых с подпиской как услугой: `PAY_MULENPAY_VAT_CODE` равен 0 (без НДС), `PAY_MULENPAY_PAYMENT_SUBJECT` равен 4 (услуга), `PAY_MULENPAY_PAYMENT_MODE` равен 4 (полный расчёт). Если у вас другая система налогообложения, спросите бухгалтера. Коды НДС: 1 это 0 %, 2 это 10 %, 6 это 20 %, 4 и 7 расчётные 10/110 и 20/120. Адрес API `PAY_MULENPAY_BASE_URL` по умолчанию `https://mulenpay.ru/api`.

## Куда вставить адрес

URL колбэка задаётся в настройках магазина в кабинете MulenPay:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

## Колбэк без подписи

У MulenPay колбэк не подписан, и по их документации так и задумано. Поэтому бот ему не верит: колбэк служит только сигналом, а статус и сумму бот берёт отдельным запросом `GET /v2/payments/{id}`. Поддельный колбэк ничего не зачислит. Секретный ключ при этом нужен для другого: им подписывается создание платежа (`sha1` от валюты, суммы, ID магазина и этого ключа).

Проверка ключей смотрит API-ключ и принадлежность магазина. Секретный ключ в такой проверке не участвует и проявится только на первом платеже: если MulenPay отвечает 400 или 422 и просит проверить ID магазина и секретный ключ, ищите ошибку там.

Тестового режима и песочницы нет, проверяйте платежом на минимальную сумму. Возвраты бот не делает, это в кабинете.
