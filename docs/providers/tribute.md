# Tribute

Оплата внутри Telegram через Tribute: покупатель платит картой (в Mini App Tribute или в браузере), счёт в рублях, евро или долларах. Бот работает через Shop API Tribute и создаёт разовые заказы.

## Настройки инстанса

Сначала проверьте, что у вашего аккаунта Tribute есть магазин. Shop API без него недоступен, а как его подключить, публичная документация не объясняет, это вопрос к поддержке Tribute. Бот при проверке ключей спросит список магазинов: если ключ верный, а список пуст, он так и скажет.

- `PAY_TRIBUTE_API_KEY`: в Tribute (@tribute или web.tribute.tg) нажмите «⋯», «Настройки», «API Keys», «Generate API Key».
- `PAY_TRIBUTE_SHOP_ID` (расширенное): номер магазина, если их несколько. Пусто означает самый старый магазин аккаунта. Если магазина с таким номером у аккаунта нет, бот не включит кассу.
- `PAY_TRIBUTE_PAY_LINK`: `telegram` (по умолчанию, оплата в Mini App внутри Telegram) или `web` (страница оплаты в браузере).
- `PAY_TRIBUTE_BASE_URL`: `https://tribute.tg/api/v1`, менять не нужно.

## Вебхук

Там же, в «Настройки», «API Keys», есть поле Webhook URL. Вставьте:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

Пустой Webhook URL бот при включении не заметит, и тогда оплаты будут доходить только проверкой статуса, с задержкой. Адрес там один на весь аккаунт, и на него приходят вообще все события (подписки на каналы, донаты, цифровые товары). События, не относящиеся к заказам бота, бот молча подтверждает ответом `{"status": "ok"}` и игнорирует. Если на одном аккаунте работают два бота или два инстанса Tribute, адрес получит только один из них.

## Подпись, лимиты, тесты

Подпись вебхука (`trbt-signature`) это HMAC-SHA256 от тела с ключом из пункта выше. Tribute не говорит, в какой кодировке её присылает, и бот принимает и hex, и base64. Сменили API-ключ в кабинете, значит, сразу обновите его и в боте, иначе подписи перестанут сходиться.

Лимиты платформы по странице Tribute: от 100 до 300 000 ₽ и от 1 до 3000 для евро и долларов. Если Tribute откажет по сумме, бот передаст пользователю, что сумма меньше минимальной или больше максимальной.

Создание заказа бот никогда не повторяет сам: у API Tribute нет ключа идемпотентности, и повтор создал бы второй заказ. Если ответ потерялся, пользователю придётся нажать оплату снова.

Тестового режима у Tribute нет, все вебхуки боевые. Проверять приходится реальным платежом на минимальную сумму, а потом возвращать деньги средствами Tribute. Частичных возвратов в API нет, только на всю сумму транзакции.
