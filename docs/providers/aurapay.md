# AuraPay

СБП и карты (Visa, Mastercard, МИР) по платёжной ссылке AuraPay, только рубли. По схеме API минимальная сумма 0,01 ₽, а реальные лимиты по способам и максимум публично не названы.

## Настройки инстанса

Все три значения лежат в кабинете cabinet.aurapay.tech, в настройках вашей кассы.

- `PAY_AURAPAY_API_KEY`: API-ключ. Уходит в заголовке `X-ApiKey`.
- `PAY_AURAPAY_SHOP_ID`: ID кассы, UUID (заголовок `X-ShopId`).
- `PAY_AURAPAY_WEBHOOK_SECRET`: «Секретный ключ #2». Им AuraPay подписывает уведомления. Это не API-ключ, и подставлять сюда его нельзя.

Расширенные поля: `PAY_AURAPAY_LIFETIME_MIN` (сколько минут счёт ждёт оплаты, по умолчанию 60, до 43200), `PAY_AURAPAY_RETURN_URL` (куда вернуть покупателя, пусто значит ссылка на бота) и `PAY_AURAPAY_BASE_URL` (`https://app.aurapay.tech`).

## Вебхук

Бот передаёт адрес в каждом счёте (`callback_url`), поэтому в кабинет его вставлять не нужно:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

Если AuraPay всё равно ничего не присылает, впишите тот же адрес в поле URL вебхука в настройках кассы.

## Слабая подпись и перепроверка

Подпись `X-SIGNATURE` считается склейкой значений полей без разделителей и без времени. Поэтому одна эта подпись ничего не гарантирует, и бот относится к ней как к слабой защите: после каждого вебхука он заново запрашивает счёт (`/invoice/status`) и зачисляет деньги только по ответу AuraPay. Список адресов отправителя AuraPay не публикует, так что проверки по IP нет.

Если ответ на создание счёта потерялся и AuraPay говорит, что такой `order_id` уже занят, бот находит счёт по номеру заказа и продолжает с ним.

Вебхука о возврате у AuraPay нет, `REFUNDED` видно только в статусе счёта, а оплаченные счета бот больше не опрашивает. Так что возврат в боте не отразится. API возврата тоже нет. Тестового режима нет: проверяйте реальным платежом минимальной суммы. Часовой пояс в датах AuraPay не указывает, поэтому срок счёта бот считает по своим часам.
