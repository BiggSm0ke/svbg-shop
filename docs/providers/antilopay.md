# Antilopay

Российские карты и СБП, рубли. Платёж создаётся через H2H API, покупатель попадает на страницу `gate.antilopay.com`, а результат приходит callback'ом, подписанным RSA. Лимиты по суммам публично не названы: если касса откажет из-за суммы, бот сообщит, что она вне лимитов проекта.

## Настройки инстанса

В кабинете lk.antilopay.com, раздел API и раздел «Проекты». Тут легко перепутать ключи, читайте внимательно.

| Поле | Что это |
|---|---|
| `PAY_ANTILOPAY_SECRET_ID` | идентификатор мерчанта (Secret ID) из раздела API |
| `PAY_ANTILOPAY_PROJECT_ID` | идентификатор проекта, вид `PE8BED46C045139256` |
| `PAY_ANTILOPAY_PRIVATE_KEY` | секретный ключ мерчанта, RSA в Base64 (PKCS#8). Всегда начинается с `MII`. Ключ для выплат боту не нужен |
| `PAY_ANTILOPAY_CALLBACK_PUBLIC_KEY` | публичный ключ проекта для проверки callback, выдаётся отдельно для каждого подтверждённого проекта |
| `PAY_ANTILOPAY_CUSTOMER_EMAIL` | почта, которую бот отправляет кассе вместо почты покупателя |

Последнее поле обязательно. Antilopay требует email или телефон покупателя в каждом платеже, а бот их не знает и не собирает. Впишите, например, адрес поддержки: данные настоящих покупателей кассе не уходят.

Остальное опционально. Если Antilopay отвечает «Данные Покупателя должны содержать ip» (код 32), укажите внешний IP сервера в `PAY_ANTILOPAY_CUSTOMER_IP`. `PAY_ANTILOPAY_VAT` (10 или 22) нужен, только если у вас ОСНО. `PAY_ANTILOPAY_PRODUCT_TYPE` по умолчанию `services`, для VPN-подписки это правильно.

## Callback

Адрес callback задаётся в настройках проекта в кабинете, в запросе создания платежа его нет:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

Требования Antilopay: только HTTPS, действующий сертификат с полной цепочкой, TLS не ниже 1.2. Если сертификат установлен неполностью (например, без промежуточного), callback не дойдёт.

## Где чаще всего спотыкаются

Публичный ключ для callback в документации описан как начинающийся с `MF`, то есть это RSA до 512 бит, а такой ключ можно взломать. Поэтому при ключе короче 2048 бит бот никогда не верит самому callback и перепроверяет платёж через `payment/check`. Лучше попросите у Antilopay ключ на 2048 бит. Та же проверка включена и при ключе нормальной длины, пока `PAY_ANTILOPAY_CONFIRM_VIA_API` включено (так по умолчанию).

Принимаются callback только с адресов Antilopay (`PAY_ANTILOPAY_ALLOWED_IPS`). За обычным Caddy это работает само, а за Cloudflare настоящий адрес не виден, и проверку выключают значением `off`.

Если запросы бота получают ошибку 22, у проекта включён белый список IP: попросите добавить адрес сервера. Callback о возврате приходит без номера заказа, поэтому бот его только подтверждает. Оплаченный платёж бот больше не проверяет, так что возврат в боте не отразится. Чарджбэк и отмену платежа (`REVERSED`) он видит по callback. Тестового режима нет.
