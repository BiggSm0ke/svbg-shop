# Pear

СБП и банковские карты на странице Pear (paypear.ru), только рубли. В боте называется Pear, а в ключах настроек стоит `PAYPEAR`.

## Настройки инстанса

Ключи в кабинете Pear.

| Поле | Откуда |
|---|---|
| `PAY_PAYPEAR_SHOP_ID` | «Настройки», «Магазин», «ID магазина» (число) |
| `PAY_PAYPEAR_SECRET_KEY` | «Интеграция», «Ключи API» |
| `PAY_PAYPEAR_PAYMENT_METHOD` | `sbp` (по умолчанию) или `card`. Pear требует способ в каждом счёте. Когда покупатель сам нажал «СБП» или «Карта», берётся его выбор, а это поле работает как запасное |

Тестового магазина у Pear нет, поэтому нужен ключ настоящего магазина.

Лимиты у Pear не публикуются, они в кабинете: «Настройки», «Способы оплаты». Перенесите их в `PAY_PAYPEAR_MIN_AMOUNT` и `PAY_PAYPEAR_MAX_AMOUNT` (в рублях), тогда бот не будет создавать счета вне лимитов. Ещё есть `PAY_PAYPEAR_RETURN_URL` (запасной адрес возврата, если бот не передал ссылку на себя), `PAY_PAYPEAR_PAYMENT_LIFETIME_MIN` (срок оплаты от 5 минут, пусто значит срок Pear) и `PAY_PAYPEAR_BASE_URL`.

## Вебхук

Адрес вебхука бот передаёт в каждом платеже. На всякий случай загляните в кабинет: «Интеграция», «HTTP-уведомления», там должны быть отмечены события `payment.confirmed` и `payment.canceled`.

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

## Проверка по IP

Алгоритм подписи (поле `signature`) Pear не публикует, и бот её не использует. Вместо неё он принимает уведомления только с адреса Pear и только с вашим `shop_id`, после чего сам запрашивает платёж через API и зачисляет деньги по этому ответу.

Из-за проверки адреса за Caddy в Docker нужна та же настройка, что и у ЮKassa: впишите подсеть прокси в `PAY_PAYPEAR_TRUSTED_PROXIES`, обычно `172.16.0.0/12`. Иначе бот видит адрес контейнера Caddy, а не Pear, и отклоняет уведомления. Список адресов Pear лежит в `PAY_PAYPEAR_ALLOWED_NETWORKS`, по умолчанию там `158.160.85.101`. Отключать проверку (`PAY_PAYPEAR_VERIFY_IP`) стоит, только если прокси не передаёт адрес клиента.

События об истечении счёта и о полном возврате Pear не присылает. Истечение бот узнаёт опросом, а оплаченные платежи он больше не опрашивает, так что полный возврат в боте не отразится. Возвраты через API у Pear по умолчанию выключены, включает менеджер, бот их не делает. Чарджбэков и рекуррентных платежей нет.
