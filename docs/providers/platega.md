# Platega

Одна касса, четыре способа: СБП, российские карты, международные карты и крипта. Работает только в рублях. В боте это разные кнопки, а на стороне Platega один мерчант.

## Настройки инстанса

Оба значения в кабинете Platega, раздел «Настройки». MerchantId при подключении выдаёт менеджер.

- `PAY_PLATEGA_MERCHANT_ID`: MerchantId в виде UUID.
- `PAY_PLATEGA_API_SECRET`: API-ключ (`X-Secret`).
- `PAY_PLATEGA_RETURN_URL` (расширенное): страница после оплаты. Если пусто, бот отправит ссылку на себя, обычно этого хватает.
- `PAY_PLATEGA_BASE_URL` (расширенное): по умолчанию `https://app.platega.io`, менять только по указанию кассы.

## Callback

В запросе создания платежа адреса для уведомлений нет, его задают в кабинете. Укажите там:

```
<PUBLIC_URL>/webhooks/pay/<instance>/<token>
```

Platega принимает только HTTPS с нормальным сертификатом и публичный адрес. Если бот не ответил, она ждёт до 60 секунд и повторяет запрос до трёх раз с интервалом 5 минут.

## Слабая подпись и лимиты

Подписи тела у Platega нет. Уведомление несёт те же заголовки `X-MerchantId` и `X-Secret`, что и ваши запросы к ней, то есть статический пароль. Поэтому бот на каждое уведомление дополнительно спрашивает статус платежа (`GET /transaction/{id}`) и зачисляет деньги по ответу кассы. Поддельное «CONFIRMED» ничего не даст, а лишний запрос в логах после каждого вебхука это нормально.

Лимитов по суммам в документации Platega нет, а валюты кроме рубля не заявлены.

Бот не передаёт кассе идентификатор покупателя (`metadata.userId`): наружу уходит только номер платежа. В документации Platega сказано, что у части категорий мерчантов без этого поля антифрод отключается. Если платежи неожиданно отклоняются, спросите у менеджера, нужен ли он для вашей категории.

Возвраты только через кабинет. Тестового режима у Platega нет. Для проверки можно завести отдельный мерчант и на время вписать его пару ключей вместо боевых. Callback чужого мерчанта инстанс отклоняет.
