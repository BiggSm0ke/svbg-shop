# Jupiter (FPGate)

P2P-процессинг: покупатель переводит деньги на реквизиты частного лица, трейдера на стороне процессинга. Это не эквайринг в обычном смысле, и риски у него другие.

**Интеграции в боте пока нет.** Мы ждём официальную документацию API из кабинета мерчанта. Публичной документации у Jupiter нет: кабинет закрыт, а сайта с описанием API найти не удалось. Когда плагин появится, по умолчанию он будет выключен, и при включении бот должен будет показать предупреждение о рисках ниже.

## Риски P2P

- Банки блокируют карты плательщиков, которые переводят деньги частным лицам (по 115-ФЗ и 161-ФЗ). Блокировку получает ваш клиент, а потом вам приходится разбираться с его жалобой.
- Возвратов через банк нет.
- Спорные платежи решает только поддержка процессинга.
- Остаток на балансе мерчанта у процессинга можно потерять, поэтому не копите там деньги.

## Что нужно для интеграции

Документ API из кабинета мерчанта с датой и версией. В нём должно быть:

- адреса боевой и тестовой среды;
- какие ключи выдаются и как подписываются запросы;
- создание счёта: поля, единицы суммы, минимум и максимум, срок жизни, способы оплаты (СБП QR, СБП по номеру, карта) и что возвращается, ссылка или реквизиты;
- получение статуса;
- уведомления: где задаётся адрес, как проверяется подпись, IP отправителя, что отвечать, как процессинг повторяет доставку;
- статусы, включая отмену, оплату не той суммой, споры и возвраты;
- есть ли тестовый режим;
- лимиты запросов, допустимые суммы, комиссии, сроки зачисления.

Достаньте документ у менеджера процессинга и передайте тому, кто ведёт бота.
